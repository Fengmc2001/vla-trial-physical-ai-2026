# 怎样看机械臂、怎样给它下任务

更新：2026-10-29。当前课题**分类 → 推出蓝块 → 黄叠蓝 → 两块一起搬到 B**已经完成一次真实 Qwen 推理加机械臂仿真的正式运行，七项阶段检查全部通过。模型从真实场景图像和完整混合语言指令中选择五个动作，机械臂依次执行。旧版分类演示单独保留；本次结果没有与旧版合并。

这是固定设置后的一个正式案例，之前另有十次开发失败，不代表任意场景或指令都能成功。本次记录了 1,202 个轨迹采样时刻，最终上下方块水平错位约 0.082 mm，红块的数值位移小于 0.001 mm。这些是仿真坐标的结果，不是实物精度。三页日文 PDF 与经过清理的公共证据已完成本地检查；70.5 秒视频也已通过最终解码与画面检查，日／英／中指令文字显示正常。代码、成片、PDF 和公共证据已发布到 [public GitHub 仓库](https://github.com/Fengmc2001/vla-trial-physical-ai-2026)；还需上传 YouTube 并完成 OmniCampus 提交。

## 场景不需要你另外提供

程序会建立一台 Franka 机械臂、蓝色／黄色／红色三个方块，以及青色托盘 A 和紫色托盘 B。每轮任务从相同的初始场景重新开始。你需要提供的是**任务文字**，不用上传场景图片、购买机械臂或手动建立三维模型。

本次多步任务使用 25 mm 方块，已保存实际尺寸与评价条件；旧分类演示使用 4 cm 方块，两个设置分别保留。这个设计不表示程序能处理任意尺寸或形状的物体。

程序也会保存每轮实际使用的物理时间步、接触求解设置和夹持力。堆叠时通过有次数与位移上限的位置反馈校正，随后缓慢松开夹爪；报告从该轮记录读取这些设置，不把调参过程当作模型训练或已经成功的证明。

本次为模拟夹爪增加了带物理碰撞的延长指，使夹爪能同时接触上下两个方块。每块指垫宽 50 mm、厚 6 mm、长 60 mm，新增质量和惯性也纳入模拟。这属于本项目修改的指部几何，不是原版 Panda 夹指；两个方块仍是独立的物理物体。这个设置通过了上述完整仿真运行，但没有制作或验证实物。

托盘在画面中的位置会受到相机视角影响，因此用“A／青色”和“B／紫色”指明目标，避免只说“左边／右边”。红色方块始终受保护，既不能搬动，也不能被当作堆叠的底座。

## 在自己的电脑上观看

执行服务器上的 `scripts/start_live.sh` 提供网页，通过 README 中的 SSH 端口转发，在自己的浏览器打开：

```text
http://127.0.0.1:17867
```

服务器负责模型、模拟和渲染，你的电脑负责显示网页。页面每秒读取最新的真实仿真相机帧；网络传输、模型等待或仿真编译时，画面可能暂时不变。它不是完整远程桌面，也不是在你的电脑上训练模型。

如果页面打不开，先检查本地 SSH 转发终端和服务器网页服务是否还在运行。网页服务最多保持两小时；同一端口已有服务时，不要重复启动多个实例。普通预览页使用另一个端口 `7866`，其中的示意图和示例动作不能当作真实机械臂视频。

## 换一台服务器时

现有场景和推理验证使用了服务器自身的共享资源准入规则。公开代码还提供 `dedicated_exclusive` 模式，可供已经获得独占 GPU 配额的使用者配置，无需原服务器的私有研究库。这个独占模式通过了 16 项 CPU 测试，尚未在真实硬件上验证，不能把它写成已经跨服务器复现成功。

在独占模式下，当前完整流程需要两张**分别独占分配的 GPU**，因为模型推理时模拟器仍在运行。推理进程的预算为 18 GiB，模拟进程为 6 GiB；各卡还要保留至少 10% 显存余量。准入程序另要求至少 64 GiB 可用内存和 32 GiB 项目磁盘余量。这些是本程序的保守准入设置，不是所有 VLM／模拟器的最低硬件要求；模型权重存储需要另算。

新服务器可参考 `configs/site.example.json`，但必须先获得实际使用权限、填写设备信息并逐项验证。示例中的两个启用开关默认都是关闭的；改变开关本身不会分配硬件或产生使用权限。独占模式会拒绝所有已有计算进程，包括自己的进程；已有任务需要共用 GPU 时，应采用经过该服务器规则核对的 `shared_adapter` 模式。

## 在哪里输入指令

在实时页面顶部的 **“输入给机械臂的要求”** 文本框输入任务。点击 **“填入当前课题指令”** 会恢复服务器当前选择的预设。当前多步课题的完整原文是：

> 青いブロックをトレーAへ、黄色いブロックをトレーBへ移してください。赤いブロックは動かさないでください。
> And then please push the blue block out of the A , and put the yellow block B on the block A.
> 最后把它们一起放到B区域中。一直都不要动红色那个块。

它的执行含义是：先把蓝色放到 A、黄色放到 B；再把蓝色从 A 推出去，把黄色叠在蓝色上；最后保持这个堆叠，把两块一起搬到 B。全程不动红色。“block A”在这里指先前被放到 A 的蓝色方块。

如果预设仍只显示第一句，说明网页当前选的是旧分类任务，并非后两种语言丢失。多步任务需由已配置的运行端选择对应任务合同，不能仅凭粘贴长指令就宣称扩展动作已验证。

待 **“执行任务”** 按钮可用后，按以下顺序操作：

1. 确认页面说明的是多步课题，文本框包含完整的三行指令。
2. 点击一次“执行任务”。程序会先检查资源，然后重新建立场景。
3. 等待真实相机图像送入模型。页面会显示当前阶段，推理期间机械臂可能静止。
4. 模型输出经过校验后才执行。依次观察分类、真实推移、堆叠，以及两块一起搬运的过程。
5. 结束后检查各阶段的独立评分。只看到最终两块在 B 不足以证明整个指令完成，还要确认中间顺序、运输时的堆叠和红块保护。

按钮灰色时，页面会说明是仍在验证、缺少当日授权，还是已有一轮任务在运行。仅修改文字不会启动 GPU 任务，不需要反复点击按钮。也不要通过修改配置绕过未完成的验证或服务器资源检查。

## 可以要求它做什么

多步模式提供四种由程序预先实现的动作：抓放、把方块推出 A、把一个方块叠到另一个上，以及把已堆叠的两块一起搬到 B。模型负责理解文字、选择对象和排列动作；它不会临时编写新的机器人控制方法。低位接触和运输走廊目前针对这一固定布局实现，暂不支持新增物体、任意推移方向、自由调整场景或任意现实世界任务。

这次使用一条日／英／中混合指令。完整运行通过只证明这个固定例子，不能直接推断各语言、任意表达或未知场景都能成功。修改后的文字会被记录为自定义任务，不能直接套用预设多步合同的成功结论。

## 怎样停止、怎样判断失败

“停止本窗口启动的任务”只针对当前网页服务自己启动的那一轮，不会停止其他研究任务。关闭浏览器标签页不会停止服务器任务；需要停止时使用该按钮。程序还设有单轮时限、动作限制和资源检查，遇到错误后不会自动无限重试。

如果页面显示失败，已有帧或已封装的录像可能仍可播放。它们可以帮助检查问题，但不能当作成功演示。详细故障和资源记录保存在内部运行目录，公开提交前需要单独筛选，避免把机器信息、个人路径或内部研究信息放入视频、报告和仓库。
